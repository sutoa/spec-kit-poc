# Data Model

This document describes the key data entities for the Consolidated Financial Account Viewer, primarily based on the data structures provided by the Plaid API and the application's needs.

## Core Entities

### User
- **Description**: Represents the individual using the application. This is an internal application concept.
- **Attributes**:
  - `id`: string (A unique identifier for the user, e.g., a UUID generated on first visit).

### Item
- **Description**: Represents a login to a financial institution, as defined by Plaid. An `Item` is created when a user successfully links an institution via Plaid Link.
- **Attributes**:
  - `id`: string (A unique identifier for this item, generated by our application).
  - `user_id`: string (Foreign key to the User).
  - `plaid_item_id`: string (The `item_id` provided by Plaid).
  - `plaid_access_token_encrypted`: bytes (The `access_token` from Plaid, encrypted using a server-side key).
  - `institution_name`: string (e.g., "Fidelity").

### Account
- **Description**: Represents a financial account associated with an `Item`. This is a transient data structure, fetched on-demand from Plaid. It is not stored in our database.
- **Attributes**:
  - `plaid_account_id`: string (The `account_id` provided by Plaid).
  - `name`: string (e.g., "Brokerage Account").
  - `mask`: string (The last 4 digits of the account number).
  - `type`: string (e.g., "brokerage", "401k").
  - `subtype`: string (e.g., "individual", "ira").
  - `balance`: number (Current balance).
  - `balance_as_of`: date (Date of the balance).

## Relationships

- A `User` can have multiple `Items` (one for each linked institution).
- An `Item` belongs to one `User`.
- An `Item` can have multiple `Accounts` (retrieved from Plaid).

## State Transitions (Plaid Link Flow)

1.  **Initiate Link**: The user clicks "Link Account" in the UI.
2.  **Get Link Token**: The frontend requests a `link_token` from our backend. The backend gets this from the Plaid API.
3.  **User Links Account**: The frontend uses the `link_token` to initialize the Plaid Link UI. The user selects their institution and enters their credentials within the secure Plaid modal.
4.  **Exchange Public Token**: Plaid Link provides a temporary, one-time use `public_token` to the frontend upon success.
5.  **Send Public Token to Backend**: The frontend sends this `public_token` to our backend.
6.  **Create Item**: The backend exchanges the `public_token` for a permanent `access_token` and an `item_id` from Plaid.
7.  **Store Item**: The backend creates a new `Item` record, storing the `user_id`, a new `id` for our system, the Plaid `item_id`, and the **encrypted** `access_token` in the PostgreSQL database.
8.  **Fetch Account Data**: The backend can now use the stored, decrypted `access_token` to fetch account information for the `Item` when the user requests a report.

## Validation Rules

- All validation of financial institution credentials is handled by Plaid's secure environment. Our application never sees or handles them.
- The `access_token` MUST be encrypted at rest in the database.
- The encryption key MUST be stored securely on the application server (e.g., in an environment variable or secrets management system) and not in the database.
